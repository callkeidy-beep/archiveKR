# 다음 메일 연결과 접속 시험

이번 기능은 **실제 SSL 로그인과 지정 폴더의 읽기 전용 접속 시험**입니다. 메일 본문 수집·첨부 저장·폴링·AI 전송·SMTP 발송은 아직 실행하지 않습니다. 접속 시험 성공은 상시 연결이나 수집 시작을 의미하지 않습니다.

## 어디서 사용할 수 있나요?

GitHub Pages는 정적 샘플이라 실제 메일에 접속할 수 없습니다. 그곳에는 비밀번호를 입력하지 마세요. 실제 기능은 Python 서버 또는 Docker 서버에서 사용합니다. 서버의 `연결·설정 → 다음 메일 접속 시험`에서 관리자 로그인 후 실행합니다.

## 다음 메일에서 먼저 준비

- 다음 메일 설정 → IMAP/POP3 → IMAP/SMTP 사용함을 저장합니다.
- 카카오계정 2단계 인증을 켜고 앱 비밀번호를 발급합니다. 카카오톡 설정 → 카카오계정 → 2단계 인증 → 앱 비밀번호에서 생성할 수 있습니다. 계정 화면의 접속용 아이디를 사용하며 일반 로그인 비밀번호는 사용하지 않습니다.
- 수집 대상으로 사용할 `보도자료`, `제보` 폴더가 실제로 존재하는지 확인하거나 실제 폴더명(예: INBOX)으로 설정합니다.
- 서버는 `imap.daum.net`, 포트993, SSL/TLS입니다. 사용자 제공 다음 메일 설정 화면에서 이 값을 확인했습니다. [다음 공식 서버 설정 안내](https://cs.daum.net/faq/service/43/category/9234/detail/24081)에서 imap.daum.net·SSL·993을 확인했습니다. [공식 인증 안내](https://cs.daum.net/faq/service/43/category/9234/detail/31143)는2025년1월2일부터2단계 인증과 앱 비밀번호가 필수라고 명시합니다. 문서 확인은 실제 계정 인증 성공을 의미하지 않습니다.

## 서버에서 안전하게 설정

```sh
npm run setup
npm run mail:setup
npm run dev
```

설정 도구는 접속용 아이디, 폴더, **다음 앱 비밀번호**, **이 앱의 관리자 비밀번호**를 묻습니다. 관리자 비밀번호는 다음 앱 비밀번호와 별개이며12자 이상으로 정합니다. 비밀번호는 터미널에 표시되지 않고 명령행 인수·로그·브라우저 저장소에 남기지 않습니다. 비밀번호를 채팅에 보내지 마세요.

계정·앱 비밀번호·시험 결과는 `.local/mail`의 암호화 저장소에 보관합니다(디렉터리0700·파일0600). 관리자 비밀번호는 scrypt 해시로 저장합니다. 기본 로컬 모드의 암호화 키 파일도 같은 개인 디렉터리에 두므로 **디스크 전체가 유출되면 암호화만으로 보호되지 않습니다**. 운영 배포에서는 `CONTENT_MAKER_ENCRYPTION_KEY`를 별도 비밀 저장소/환경변수로 주입하고 암호문과 분리합니다. `.env`를 쓰면 파일 권한0600과 디스크 암호화를 적용하세요. 키를 잃으면 암호화 저장소를 복원할 수 없습니다.

외부 키는 서버에서 `cryptography.fernet.Fernet.generate_key()`로 생성하는32바이트 URL-safe Base64 형식입니다. 키는 비밀이며 채팅/화면/로그/Git/공개 빌드에 넣지 않습니다. `.env.example`에는 값 없이 이름만 기록합니다. 안전하게 주입한 환경값은 `.env`가 덮어쓰지 않습니다. 앱 비밀번호의 평문 `.env` 저장은 지원하지 않습니다.

## 관리자 로그인과 시험 결과

서버 화면에서 관리자 비밀번호로 로그인하고 ‘접속 시험’을 누릅니다. 앱 비밀번호를 웹 화면에 다시 입력하지 않습니다. 세션은 HttpOnly·SameSite 쿠키로 관리하고 만료됩니다. 원격 접속은 HTTPS와 허용 호스트 설정이 필요합니다. 기본은 로컬 HTTP만 허용합니다.

시험은 SSL 인증서 검증 → LOGIN → CAPABILITY → 지정 폴더 LIST/EXAMINE/STATUS → LOGOUT 순서입니다. 읽기 전용 EXAMINE만 쓰고 FETCH/STORE/이동/삭제/SMTP를 호출하지 않습니다. 한글 폴더명은 modified UTF-7로 인코딩합니다. IDLE은 서버의 광고 여부만 표시하고 실제 IDLE 동작을 시험했다고 표시하지 않습니다.

모든 지정 폴더 확인에 성공한 최근 결과만 ‘최근 접속 시험 성공’입니다. 결과가 오래됐거나 인증/네트워크/폴더 시험이 실패하면 연결 성공으로 표시하지 않습니다. 계정 재설정은 이전 결과와 세션을 무효화합니다. 원문이나 서버 예외 전문 대신 안전한 오류코드를 표시합니다.

## Docker

로컬 설정 도구 대신 컨테이너에서 `docker compose run --rm engine python -m app.mail_setup`을 실행해 영속 볼륨에 설정합니다. 이후 `docker compose up --build -d`. 볼륨을 삭제하면 설정도 삭제됩니다. 운영 외부 키는 동일한 비밀 키를 설정 명령과 실행 컨테이너 양쪽에 안전하게 주입해야 합니다. 기본 compose는 루프백 포트만 공개합니다. 컨테이너에선 로컬 브라우저 요청도 Docker 게이트웨이 IP로 보일 수 있습니다. 이 경우 `docker inspect <컨테이너ID> --format '{{range .NetworkSettings.Networks}}{{.Gateway}}{{end}}'`로 게이트웨이를 확인하고 `.env`의 `CONTENT_MAKER_TRUSTED_HTTP_PEERS`에 **해당 IP/32 하나만** 설정한 뒤 compose를 다시 실행합니다. HTTP 주소는 여전히 localhost만 허용합니다. 포트를 외부에 노출하지 말고, 원격 운영은 HTTPS와 정확한 `CONTENT_MAKER_TRUSTED_HOSTS`를 사용하세요. 임의의 X-Forwarded-For는 신뢰하지 않습니다.

서버 네트워크에서 DNS와 외부 TCP993이 허용돼야 합니다. HTTPS 프록시만 지원하는 환경에서는 IMAP 연결이 되지 않을 수 있으며, 비밀번호를 바꿔도 네트워크 제한은 해결되지 않습니다.

## 범위와 검증 구분

가짜 IMAP 어댑터 테스트는 읽기전용 명령·오류처리·인증·암호화를 검증합니다. 실계정 인증 성공을 대체하지 않습니다. 실제 연결됨 표시는 사용자가 앱 비밀번호를 서버에 설정하고 접속 시험에 성공해야만 나타납니다. 메일 원문 수집·분류 연동은 별도 후속 작업입니다.
