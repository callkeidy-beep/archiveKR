# 휴대폰에서 서버 배포와 다음 메일 등록

휴대폰 브라우저에서 쓸 수 있도록 **HTTPS 서버 배포 구성과 계정 등록 화면을 준비한 상태**입니다. 아직 사용자의 Render 계정에 서버를 만들거나 요금을 결제하지 않았습니다. 실제 서버 주소와 다음 메일 연결 성공 결과도 아직 없습니다.

현재 공개 GitHub Pages는 샘플입니다. 실제 메일 계정이나 비밀번호를 등록하는 곳이 아닙니다. 아래에서 배포한 **본인 Render 서비스의 HTTPS 주소**에서만 계정을 등록합니다. 메일 본문 수집·첨부 추출·자동 송고는 이번 기능에 포함되지 않습니다.

## 준비할 것

- GitHub 계정과 저장소 `callkeidy-beep/content-maker-engine`
- Render 계정 및 유료 웹 서비스·영속 디스크 결제 수단
- 다음 메일 설정 화면에 표시된 접속용 아이디
- 다음 IMAP 사용 설정, 카카오계정 2단계 인증, 다음 앱 비밀번호

Render의 현재 가격과 제공 조건은 생성 화면에서 직접 확인합니다. 이 프로젝트의 Blueprint는 영속 저장을 위해 유료 Starter 서비스와 디스크를 사용하도록 제안합니다. **결제 조건을 확인한 뒤 본인이 서버 생성을 결정해야 합니다.** 이 안내나 코드 실행만으로 결제를 대신 진행하지 않습니다.

## 1. Render에서 배포 구성 열기

휴대폰 Chrome 또는 Safari에서 아래 링크를 엽니다.

**[Render 배포 구성 열기](https://render.com/deploy?repo=https://github.com/callkeidy-beep/content-maker-engine)**

1. Render에 가입하거나 로그인합니다.
2. GitHub 연결을 요청하면 `content-maker-engine` 저장소에 대한 필요한 접근만 허용합니다.
3. 배포 설정에서 저장소와 `render.yaml`을 확인합니다. 링크로 자동 선택되지 않으면 Render의 **New → Blueprint**에서 저장소를 선택합니다.
4. 서비스·디스크·지역·월 비용을 검토합니다. 원치 않는 추가 서비스가 있으면 진행을 멈추고 설정을 확인합니다.
5. 본인이 생성/배포를 승인하고 빌드 완료를 기다립니다.

메뉴 이름과 요금은 Render에서 바뀔 수 있습니다. 이 개발 환경에서는 Render 공식 도움말의 최초 조회가 네트워크403으로 차단돼 현재 화면·가격·IMAP 연결 가능 여부를 실제로 검증하지 못했습니다. 배포 중 Render가 `render.yaml` 오류를 표시하면 오류 문구를 확인합니다. 비밀값이 표시된 화면은 공유하지 않습니다.

## 2. 서버 주소와 첫 설정 코드 확인

배포가 성공하면 Render 서비스 화면에 `https://…onrender.com` 주소가 표시됩니다. 이것이 실제 서버입니다. GitHub Pages 주소와 다릅니다.

1. 서비스의 **Environment**에서 `CONTENT_MAKER_SETUP_TOKEN`을 찾습니다.
2. Render가 자동 생성한 값을 본인 휴대폰에서만 복사합니다. 이는 첫 관리자 등록을 허용하는 임시 설정 코드입니다.
3. 서버의 HTTPS 주소를 열고 **연결·설정** 메뉴로 갑니다.
4. **첫 관리자 등록** 화면에서 설정 코드와 새 관리자 비밀번호를 입력합니다. 비밀번호 확인도 입력합니다.
5. 등록이 끝나면 관리자 비밀번호로 로그인합니다.

설정 코드는 채팅·이슈·Git·공개 샘플·스크린샷에 보내지 않습니다. 등록이 완료되면 코드는 다시 관리자 등록에 사용할 수 없습니다. 정상 로그인까지 확인한 뒤 운영자가 `CONTENT_MAKER_SETUP_TOKEN` 환경변수를 제거할 수 있습니다. 계정을 복구하려고 암호화 키를 바꾸거나 디스크를 지우면 안 됩니다.

## 3. 다음 메일 계정 등록

관리자 로그인 후 **다음 메일 등록**에서:

1. 다음 메일 설정 화면에 표시된 **접속용 아이디**를 입력합니다.
2. 다음에서 발급한 **앱 비밀번호**를 입력합니다. 일반 로그인 비밀번호가 아닙니다.
3. 읽기 시험할 실제 폴더 이름을 입력합니다. 예: `보도자료`, `제보`. 폴더가 없다면 먼저 다음 메일에서 만들거나 실제 폴더명으로 바꿉니다. 접속 확인만 하려면 표준 받은편지함 이름 `INBOX`를 지정할 수 있습니다.
4. 저장합니다. 비밀번호는 서버에 암호화해 보관하며 웹 화면에 다시 표시하지 않습니다.
5. 계정 저장으로 기존 세션이 종료되면 **앱 관리자 비밀번호**로 다시 로그인합니다.
6. **읽기 전용 접속 시험**을 누릅니다.

### 서로 다른 세 가지 비밀값

| 이름 | 용도 | 어디서 받거나 만드는가 |
|---|---|---|
| 첫 설정 코드 | 첫 관리자 등록 권한 확인 | Render의 `CONTENT_MAKER_SETUP_TOKEN` |
| 앱 관리자 비밀번호 | 콘텐츠메이커 엔진 로그인 | 첫 관리자 등록에서 직접 설정 |
| 다음 앱 비밀번호 | 다음 IMAP 인증 | 카카오계정의 2단계 인증·앱 비밀번호 메뉴 |

세 값을 서로 바꿔 쓰거나 같은 값으로 정하지 않습니다. 다음 앱 비밀번호를 채팅으로 전달하지 않습니다. HTTPS 주소가 맞는지 확인한 뒤 자신의 서버 등록 화면에만 입력합니다.

## 4. 접속 시험 결과 읽기

- **최근 시험 성공**: SSL 인증서 검증과 모든 지정 폴더의 읽기 전용 확인에 성공한 최근 결과입니다. 상시 접속이나 메일 본문 수집이 시작됐다는 뜻은 아닙니다.
- **인증 실패**: 접속용 아이디, 앱 비밀번호, IMAP 사용 설정과 2단계 인증을 확인합니다.
- **폴더 확인 실패**: 입력한 폴더가 실제로 존재하는지 확인합니다. 한글 폴더명도 지원합니다.
- **네트워크·TLS 실패**: 서버에서 `imap.daum.net` DNS 조회와 외부 TCP993 연결, 인증서 검증이 가능한지 확인합니다. 앱 비밀번호를 반복해서 바꿔도 서버 네트워크 제한은 해결되지 않습니다.
- **이전 결과 만료/설정 변경**: 새 접속 시험을 실행합니다. 오래된 결과나 다른 계정의 성공 결과를 연결 성공으로 재사용하지 않습니다.

Render에서 외부 IMAP993이 실제로 허용되는지는 **배포 후 실제 접속 시험으로 확인해야 합니다**. 이 문서는 SMTP 포트 정책을 IMAP 허용 근거로 사용하지 않습니다. Render와 다음 메일의 접근 정책·네트워크 상태에 따라 연결되지 않을 수 있으며, 성공 결과가 없으면 미연결로 남깁니다.

시험은 메일을 읽음 처리하거나 이동·삭제하지 않습니다. 본문과 첨부를 내려받지 않고 메일도 발송하지 않습니다. IDLE은 서버가 지원을 광고하는지와 실제 시험 여부를 구분합니다.

## 5. 키와 데이터를 유지하기

- `CONTENT_MAKER_ENCRYPTION_SECRET`은 Render가 자동 생성한 **서버 암호화용 난수**입니다. 계정 저장소와 다른 Render 비밀 환경변수로 보관합니다. 사용자가 외우는 짧은 비밀번호를 대신 넣지 않습니다.
- 이미 계정을 저장했다면 암호화 비밀값을 다시 생성하거나 변경하지 않습니다. 키가 바뀌거나 사라지면 저장된 계정을 해독할 수 없습니다.
- `/data` 영속 디스크에는 암호화 계정 설정과 샘플 평가가 남습니다. 서비스를 재배포해도 같은 디스크·키를 유지해야 합니다.
- 키 복구본은 암호화 데이터 백업과 분리해 안전하게 보관합니다. 키나 원본 앱 비밀번호를 Git 저장소·공개 파일·대화에 넣지 않습니다.
- 주간 자동 백업과 외부 백업 저장소는 아직 구현하지 않았습니다. 영속 디스크가 자동 백업·실제 복원 시험을 대신하지 않습니다.
