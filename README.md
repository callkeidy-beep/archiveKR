# archiveKR

현재 활성 기능은 **취재·편집 데스크**, **영화·카드뉴스 제작실**, **수집·제작·배포 자동화**입니다. 기회탐색과 지역뉴스는 코드·기존 데이터를 삭제하지 않고 잠시 분리해 보관합니다.

## 자동화 흐름

MOVIST 홈페이지 신규 기사 탐색 → 실제 본문 수집 → 데스크 원고 등록 → 원문 기반 기획 발췌·Instagram 캡션·Threads 문안·1080×1440 PNG 카드 제작 → 역할별 판단·에이전트 메시지 → 사용자 최종 승인 → 선택한 채널 게시.

데스크에 직접 등록한 원고도 같은 큐를 사용합니다. 제목만 등록하면 본문 입력을 기다리며, 본문을 저장하면 별도 지시 없이 제작을 시작합니다. 원문은 보존하고 제작 결과는 별도로 기록합니다. 현재 제작은 **발췌·템플릿 방식**이며 새로운 취재나 AI 검증으로 표시하지 않습니다. 영화 편집기의 선택 AI 기능과는 별개입니다.

워커는 앱 서버가 켜져 있는 동안 실행됩니다. 5분마다 새 기사 목록을 확인하며 첫 탐색은 기존 목록을 기준으로 저장하고 이후 새 URL만 자동 인계합니다. 과거 기사는 URL로 직접 수집할 수 있습니다. 기사 URL 중복을 방지하고 큐·작업 결과·게시 상태를 파일에 보존합니다. 공개 운영 서버가 배포되지 않았으므로 머신이 꺼져 있는 동안 실행되지는 않습니다.

### SNS 연결

- Threads: `THREADS_USER_ID`, `THREADS_ACCESS_TOKEN` 및 게시 권한.
- Instagram: `INSTAGRAM_USER_ID`, `INSTAGRAM_ACCESS_TOKEN`, `ARCHIVEKR_PUBLIC_MEDIA_BASE_URL`. Meta가 접근할 수 있는 실제 공개 HTTPS 카드 경로가 필요합니다.

토큰은 안전한 서버 환경 설정에만 넣습니다. 화면에는 연결 여부만 표시합니다. 채널이 연결되지 않아도 원고·문안·카드는 제작하고 사용자 승인을 기다립니다. 승인 이후에도 연결이 없으면 배포를 `blocked`로 구분합니다. 계정이 연결되어도 최종 승인 전에는 게시하지 않습니다. 사용자가 제작 버전과 게시 계정을 승인한 채널만 워커가 게시합니다. 게시 응답이 불명확한 작업은 자동 재전송하지 않으며 실제 계정에서 확인해야 합니다. 이미 게시된 기사는 원고 수정만으로 중복 게시하지 않습니다.

## 개발

```bash
cd /workspace/archiveKR
npm run setup
npm run dev
```

Node.js 24+, Python 3.12가 필요합니다. 통합 서버 포트는 3100, 영화 서버는 3102이며 `npm run dev`가 두 서비스를 관리합니다. Node는 지원되는 환경 프록시를 사용하고 TLS 검증을 유지합니다. 앱은 로컬 개발용이며 직원 인증·운영 배포·공개 미디어 호스팅은 별도 연결이 필요합니다.

```bash
npm run validate
modules/movist/.venv/bin/python -m unittest discover -s modules/movist -p 'test_*.py'
```

자동화 테스트는 실제 SNS에 게시하지 않고 임시 데이터와 대체 전송기를 사용합니다. `ARCHIVEKR_AUTOMATION_BACKGROUND=0`은 테스트 서버의 자동 워커만 끄는 옵션입니다.

## 파일과 보존

- 원고·큐·자동화 설정: `.local/data.json` (`ARCHIVEKR_DATA_FILE`로 변경)
- 자동 카드: 같은 데이터 파일 디렉터리의 `automation/`
- 영화 편집기 보관함·내보내기: `modules/movist/data/`, `modules/movist/output/`
- 분리한 원본: `modules/opportunity-radar/`, `modules/regional-news/` — 기존 기능과 테스트 보존

ignored 데이터는 GitHub에 올라가지 않으므로 이전 시 별도 백업이 필요합니다. 자동화 데이터는 단일 서버 프로세스용입니다. 계정 토큰·첨부 ZIP의 config.env는 커밋하지 않습니다.

기회탐색 원본 커밋은 `9b74d67a0f295a08b74450e891eeb925c29eeda1`, 영화 제작실은 사용자 제공 `movist-auto.zip` 및 카드 규격 XLSX를 기반으로 합니다. 기존 ChatGPT Sites 두 곳의 데이터·권한은 복원하지 않았습니다. 자동화는 이 프로젝트에서 새로 구현한 기능입니다. 실제 사이트·API가 실패하면 본문 수집·게시 성공으로 보고하지 않습니다.

## 이번 변경 검증과 남은 연결

Node 테스트 47개와 Python 테스트 11개가 통과했습니다. 임시 저장소를 사용하는 실제 브라우저에서 원고 등록 → 별도 지시 없는 카드·문안 제작 → 역할 메시지 → 수정 요청 → 재제작 → 선택 채널 최종 승인 → 수정 시 승인 만료 → 게시 거절과 모바일 화면을 확인했습니다. 사진 배경의 실제 PNG 크기·이미지 반영도 검사했습니다. 외부 게시 테스트는 대체 전송기로 실행했으며 실제 SNS에 테스트 글을 보내지 않았습니다.

MOVIST 홈페이지 기사 목록 9개는 실제 응답으로 확인했습니다. 본문을 공급하는 공식 `m.movist.com` HTTPS API는 허용 설정 후에도 마지막 요청에서 503을 반환했습니다. 본문 연결 복구와 SNS 계정·공개 미디어 주소 설정 전에는 수집부터 실제 게시까지 모두 완료됐다고 볼 수 없습니다.

## 역할별 협업과 최종 승인

자동화가 새 기사를 데스크에 전달하면, 데스크가 출처·본문을 점검하여 제작실에 요청하고, 제작실이 사진/텍스트 카드 가능 여부와 실제 제작 결과를 응답합니다. 자동화는 완성된 제작물을 승인함으로 전달합니다. 역할별 판단은 규칙 기반이며 LLM 간 자유 대화가 아닙니다. 메시지는 기사 작업·제작 버전·발신/수신 역할·응답 관계·시각과 함께 보존됩니다.

사용자는 승인함에서 문안·원문·카드와 게시 계정을 검토하고 승인/수정 요청/거절을 결정합니다. 수정 요청은 데스크·제작실 메시지로 전달됩니다. 승인된 제작물과 원문·채널·계정이 달라지면 승인이 만료됩니다. 이전 버전 승인을 새로운 제작물이나 계정에 적용하지 않습니다. 반려와 수정 요청은 서버 재시작·재시도로 풀리지 않습니다. SNS 계정 연결만으로 게시되지 않습니다.

카드는 제작 버전별 불변 파일로 보관하여 비동기 게시 중 다른 이미지로 바뀌지 않도록 합니다. 게시 직전에도 승인된 버전·결정·채널·계정을 확인합니다. 사용자 승인 요청 API는 동일 출처의 로컬 앱에서만 받습니다. 운영용 로그인·사용자 권한은 여전히 별도 구축이 필요합니다.

이미 게시한 원고를 수정하면 이전 게시 ID·시각은 보존하고 새 제작물에 대한 승인을 요청합니다. 이 승인은 기존 게시물 수정이 아니라 새로운 SNS 게시를 허용합니다. 늦은 외부 응답도 원래 승인 버전의 이력으로 기록하며 새 승인 상태를 덮어쓰지 않습니다.

## archiveKR 메인 통제와 최종 MOVIST 제작 흐름

archiveKR이 수집·데스크·제작실을 지휘합니다. 수집 완료 → 데스크 원고 정리 → 실제 사진 수로 제작 요청 → 제작실 출처·사용권 확인 요청 → archiveKR의 사용자 승인 요청이 작업별 메시지함에 이어집니다. 판단은 규칙 기반이며 사실 확인이나 사진 권리 확인을 AI가 대신 완료했다고 표시하지 않습니다.

자동 제작은 최종 XLSX 디자인(1080×1440, 가운데 MOVIST, 흰 테두리 태그, 표지 부제 숨김)을 사용합니다. 기사 사진 최대 3장으로 카드 묶음을 만들며 사진이 없으면 텍스트 카드로 표시합니다. 자동 표지 제목은 원제에서 최대 26자를 발췌해 두 줄로 배치하고 전체 원제는 문안에 보존합니다. Instagram·Threads·카카오용 문안을 함께 생성하고 제작실에서 편집을 이어갑니다.

사진이 있는 제작물은 해당 버전의 사진 출처·사용권 확인 체크와 최종 승인 후에만 연결된 SNS에 게시할 수 있습니다. Instagram은 여러 장이면 캐러셀로 처리하고, 각 API 호출 전에 승인·카드 전체 해시를 다시 확인합니다. 카카오는 문안·카드 다운로드까지 제공하며 자동 게시 계정/API는 연결하지 않았습니다. 공개 GitHub Pages 사이트는 브라우저 전용 체험판으로 실제 수집·SNS 게시를 실행하지 않습니다.
