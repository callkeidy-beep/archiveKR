# archiveKD 공개 체험

기존 화면 위에 브라우저 전용 API 어댑터를 얹어 원고 등록 → 규칙 기반 판단·문안·PNG 제작 → 역할별 메시지 → 사용자 승인·거절·수정 요청 → 변경 후 재승인을 체험합니다.

실제 서버, 콘텐츠 수집, AI 작성, SNS 게시, 계정 인증 기능은 연결하지 않습니다. 승인 후에도 게시 상태는 차단으로 유지합니다. 초기 원고는 가상의 체험 자료이며 실제 기사·운영 데이터·비밀을 포함하지 않습니다. 데이터와 버전별 제작·결정 기록은 이 브라우저의 localStorage에만 보관합니다. 공유 기기에서는 체험 데이터 초기화를 사용하세요. 민감한 원고를 입력하지 마세요.

`demo-api.js`는 기존 화면의 `/api/` 호출을 브라우저 메모리와 localStorage로 처리합니다. 외부 네트워크 요청은 실행하지 않습니다. `studio.html`은 별도의 단순 체험 편집기로, 실제 영화 모듈의 AI·영상 편집기 전체를 복제하지 않습니다. 제작실에서 입력한 제목·본문을 데스크에 저장하면 규칙 기반 문안을 새로 만듭니다. 제작실에서 수동으로 수정한 SNS 문안을 실제 게시하는 기능은 없습니다.

상태가 바뀐 원고는 고유 제작 버전을 받고 기존 결정은 기록으로 남으며 재승인이 필요합니다. 사용자 승인 요청은 현재 버전과 게시 대상의 일치 여부를 검사하며 이미 결정된 버전의 중복 결정은 거부합니다. 로컬 체험 데이터는 인증·권한·감사 저장소가 아니므로 운영 승인 증거로 사용할 수 없습니다.

## 빌드와 공개

루트에서 `npm run build:preview`로 `site-dist/`를 생성합니다. 외부 의존성 없는 정적 사이트이며 하위 경로에서도 실행됩니다. 생성물만 `gh-pages` 브랜치에 배포합니다. 이 브랜치는 체험용이며 실제 서버 데이터는 포함하지 않습니다.

GitHub Pages가 아직 활성화되지 않았다면 저장소 Settings → Pages → Build and deployment에서 Deploy from a branch, `gh-pages`, `/ (root)`를 저장해야 합니다. 활성화 및 GitHub 배포 완료 후 예상 주소는 https://callkeidy-beep.github.io/archiveKR/ 입니다. 브랜치 푸시만으로 공개 사이트 활성화를 보장하지 않습니다.

최종 콘텐츠 표지 체험은 1080×1440(3:4), 콘텐츠 26px 중앙, 흰색 24px 외곽선 태그(56px), 제목 84px·최대 2줄·줄당 13자, 좌우 60px, 45%→92% 구간 그라데이션, 표지 본문 없음, 우하단 출처 20px를 적용합니다. 실제 사진을 가져오지 않는 체험용 텍스트 시안이며, 사진이 있는 완성 카드와 구분합니다. `card-renderer.js`는 `demo-api.js`보다 먼저 로드해야 합니다. 배포 빌더가 `fonts/head.ttf`, `fonts/body.ttf`를 제공하면 해당 글꼴을 사용하고, 없으면 브라우저 대체 글꼴입니다.

archiveKD이 메인 통제자이며 자동화→데스크→제작실→데스크→archiveKD→사용자 메시지를 남깁니다. 실제 등록된 사진 수만 표시하고, 카카오용 문안도 생성합니다. 사진이 등록된 경우 사진 사용 확인과 최종 버전 승인이 필요합니다. 사진 없는 텍스트 시안은 사진 확인 항목이 필요하지 않습니다. 승인해도 이 공개 체험은 외부 플랫폼에 전송하지 않습니다.
